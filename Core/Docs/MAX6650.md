# MAX6650 Fan Controller — Implementation Guide

This document describes how to finish the MAX6650 driver in `Core/Drivers/Src/fan.c` and where to configure board-specific values.

NOTE: the repository currently contains a robust, configurable driver with placeholder `#define`s. To complete the implementation you must supply the MAX6650 datasheet or the correct register map and 7-bit I2C address for your board.

Required information (from datasheet or board schematic):
- 7-bit I2C address (e.g. `0x2F`). This should be defined as `MAX6650_I2C_ADDR` (shifted left 1 for HAL API expects 8-bit address).
- Register address for PWM command (write) and whether a register address must be sent prior to write.
- Register address(s) for RPM/tachometer read and the format (bytes, MSB/LSB order, units).
- Any configuration registers required at init (mode, resolution, prescalers, tachometer divisor, etc.).

Driver expectations
- `fan_init()` will probe the device using `HAL_I2C_IsDeviceReady()` and set `fan_t.present`.
- `fan_set_pwm(uint8_t)` writes a single register with the PWM value (0..255) unless the device uses a scaled range.
- `fan_poll()` reads RPM (2 bytes) and sets `fan_t.rpm` and `fan_t.fault` when RPM==0 or I2C errors occur.

How to finalize
1. Open the MAX6650 datasheet and locate:
   - I2C address (7-bit)
   - PWM register address and write format
   - RPM/tach register address and read format
   - Any other required init/config registers
2. Replace the placeholder defines in `Core/Drivers/Src/fan.c` or override them at build time via `-DMAX6650_I2C_ADDR=...`.

Example (pseudo):

```
#define MAX6650_I2C_ADDR ((0x2F) << 1)
#define MAX6650_REG_PWM 0x05
#define MAX6650_REG_TACH_MSB 0x06
#define MAX6650_REG_TACH_LSB 0x07
```

3. If the device requires reading a device ID register, add a `fan_probe()` helper to validate part revision.
4. If RPM requires conversion (divider, or fan-specific pulse-per-rev), implement the conversion and document units in `fan.h` and `Core/Docs/METHODS.md`.

Testing
- Add host-unit tests that mock `hi2c2` HAL calls, or run on hardware and observe that `fan_init()` sets `present==true` and `fan_poll()` returns non-zero `rpm` when fan spins.

If you provide the datasheet or the key register values, I will patch `Core/Drivers/Src/fan.c` to use exact registers and conversions and update `fan.h` and `METHODS.md` accordingly.
